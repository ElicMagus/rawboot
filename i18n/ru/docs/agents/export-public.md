# Публикация публичного репозитория

Внутренний репозиторий Gitea — канонический. Публичный репозиторий GitHub
(`https://github.com/ElicMagus/rawboot`) — зеркало с переписанной историей
(ADR-0016). Старый экспорт одним сжатым коммитом выведен из эксплуатации.

## Что публикуется

- `master` вплоть до тега `v0.1.0` (207 коммитов) и сам аннотированный тег.
- Каждый отслеживаемый файл, кроме `.gitea/`, `scripts/export-public.sh`,
  `scripts/issue-view.sh`, `target/` и `embed/`.
- Код, окружение и решения, включая `AGENTS.md`,
  `CODING_STANDARDS.md`, `docs/agents/` и `research/`.
- Коммиты, сделанные после тега (этот runbook, инструменты миграции, дерево
  `i18n/` и позднейшие исправления), добавляются сверху как обычные публичные
  коммиты.
- Незамерженные внутренние ветки не публикуются; сначала мерж, затем ручная
  публикация.

## Переписывание

История переписывается с помощью `git-filter-repo`:

- удалить перечисленные выше внутренние пути из каждой ревизии;
- сохранить даты автора и коммиттера, а также настоящие имена и адреса
  электронной почты;
- заменить секреты и пароли, путь к внешнему файлу токена, домашние пути вида
  `/home/<user>` и ссылки на внутреннюю Gitea нейтральным текстом;
- сохранить темы и тела коммитов на русском.

Сообщение тега, тегирующий и дата сохраняются; меняется только цель тега.

## Проверочные шлюзы

Все четыре блокирующие; запускайте их на чистом клоне перед любым пушем.

1. **Дифф манифеста.** `scripts/migrate/` экспортирует манифест из Gitea и из
   GitHub, затем сравнивает номера, типы, состояния, тела, метки, веху, число и
   тела комментариев, а также рёбра blocked-by. Требуется ноль различий.
2. **Сканирование секретов.** Grep по каждому историческому блобу
   (`git rev-list --objects --all`) и по каждому тексту трекера на шаблоны
   токенов и паролей, путь к файлу токена, `/home/<user>` и ссылки на внутреннюю
   Gitea.
3. **Сборка.** `scripts/check.sh` проходит в переписанном клоне.
4. **Выборочная проверка.** Десять issue сверяются вручную с Gitea.

## Разовая миграция

1. Заморозить нумерацию Gitea: не создавать ни issue, ни pull request, пока не
   закончится шаг 5, иначе номера GitHub сдвинутся навсегда.
2. Взять бандлы: внутренний `git bundle` для `master` вместе с тегами и бандл
   текущего публичного `main`.
3. Пробный прогон во временном каталоге: переписать, прогнать все шлюзы,
   подсчитать коммиты, подтвердить цель тега.
4. Отрепетировать трекер в одноразовом репозитории: создать все 56 объектов в
   возрастающем порядке и сравнить манифест.
5. Запушить переписанный `main` с `--force` и запушить тег `v0.1.0`.
6. Создать метки и веху, затем создать объекты #1–56 в возрастающем порядке.
   Pull requests архивируются как закрытые записи с временной базовой веткой и
   телом, которое ссылается на настоящий merge-коммит. Импортировать 72
   комментария, рёбра blocked-by и двуязычный текст EN/RU (английский сверху,
   русский оригинал в `<details>`).
7. Удалить временные базовые ветки и повторить шлюзы.

## Публикация позднейшего исправления

1. Влить исправление во внутренний `master` и поставить тег, если это релиз.
2. Переписать свежий клон теми же фильтрами и прогнать шлюзы.
3. Запушить переписанный `main` и любой новый тег. Новые коммиты появятся после
   `v0.1.0`.

## Трекер

GitHub issues и pull requests — архив только для чтения; не создавайте новые
там. Gitea остаётся единственным живым трекером.

## Оговорки

- Force-push необратим: бандлы из шага 2 — единственный путь назад.
- GitHub выставляет метки времени issue, комментариев и pull request на дату
  миграции; каждое тело записывает исходную дату.
- Внутренний почтовый домен остаётся видимым в метаданных коммитов по решению
  владельца.
