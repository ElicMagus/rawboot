# Доменные доки

Как инженерные навыки должны использовать доменную документацию этого репозитория при исследовании кодовой базы.

## Перед исследованием прочитайте

- **`GLOSSARY.md`** в корне репозитория, или
- **`GLOSSARY-MAP.md`** в корне репозитория, если он существует: он указывает на один `GLOSSARY.md` на контекст.
- **`docs/adr/`**: прочитайте ADR, затрагивающие область, в которой вы собираетесь работать.

Если какой-либо из этих файлов не существует, **продолжайте молча**. Не отмечайте их отсутствие; не предлагайте создать их заранее. Навык `/domain-modeling` создаёт их лениво, когда термины или решения действительно проясняются.

## Источники upstream parity

Для работы по parity получайте закреплённое upstream C-дерево вместо угадывания URL:
`scripts/fetch-upstream.sh` (по умолчанию использует SHA из заметок исследования parity) записывает
его в `target/upstream/awboot-<sha>/`. Ссылайтесь на upstream по файлу и строке; на наш код
ссылайтесь по символу.

Начните с `research/parity-checklist.md`: он сопоставляет каждый модуль loader в области видимости
с его upstream-источником, локальным кодом и чек-листом расхождений по функциям.

## Структура файлов

Репозиторий с одним контекстом:

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-rust-port-and-license.md
│   └── ...
└── src/
```

## Используйте словарь глоссария

Когда ваш вывод называет доменное понятие (в заголовке issue, предложении по рефакторингу, гипотезе, имени теста), используйте термин в том виде, в каком он определён в `GLOSSARY.md`. Не уходите к синонимам, которых глоссарий явно избегает.

Если нужного понятия ещё нет в глоссарии, это сигнал: либо вы изобретаете язык, который проект не использует (пересмотрите), либо существует реальный пробел (отметьте его для `/domain-modeling`).

## Отмечайте конфликты ADR

Если ваш вывод противоречит существующему ADR, выявите это явно, а не переопределяйте молча:

> _Противоречит ADR-0004 (состояние CPU на handoff), но стоит переоткрыть, потому что…_

## Ссылайтесь на код по символу, а не по строке

На upstream (`szemzoa/awboot`) ссылаются по закреплённому файлу и строке, потому что это дерево
никогда не двигается. На **наш собственный** код ссылайтесь по символу (`sunxi_gpio_set_pull`,
`ccu::USART_BGR_REG`), никогда по номеру строки: наши файлы меняются, и ссылка `mod.rs:120`
превращается в неверный факт.
