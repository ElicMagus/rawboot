# Выровнять поведение loader по upstream awboot, сохранив собственное выражение на Rust

Аппаратная логика loader выровнена по *поведению* `szemzoa/awboot`, привязанному
к закреплённому коммиту upstream, а не по его коду: мы совпадаем по порядку
шагов, константам, структуре ветвлений и таблицам поиска, но сохраняем
собственное выражение под CC-BY-4.0 (ADR-0001). Имена перенимают `snake_case`
upstream, чтобы общий словарь переносился; типы, трейты, `Result`/`?` и аксессоры
регистров остаются идиоматичным Rust.

Вне объёма: пути upstream для Linux/FDT/PSCI/secure-monitor/FatFs и пути SoC,
отличных от T113-S3 (T113-S4, V851s), — ни один из них не использует наш
контракт собственной прошивки (ADR-0002). Перевыравниваются только драйверы,
которые у нас уже есть; драйверы upstream, которых нам не хватает (DMA,
SPI-NAND, watchdog, помощники кэша/исключений), откладываются до тех пор, пока
функция их не потребует. Parity проверяется дымовым прогоном hardware-in-the-loop
на T113-S3 по чек-листу расхождений.

## Имена

Имена upstream применяются к функциям, константам, полям регистров и поведению.
Типы Rust, поля структур и варианты enum — наши: `SdhciCmd.idx` — это
идиоматичное написание upstream-поля `cmd.idx` на Rust, а поле-обёртка может
быть названо по смыслу, а не скопировано из C-структуры. Переименование поля не
является нарушением parity, когда форма типа в порте меняется.

## Граница тикета

Parity-тикет может адаптировать непосредственных вызывающих драйвера, который он
перевыравнивает, к новому API и исправлять блокирующие баги, нужные чтобы
сделать его собственные критерии приёмки тестируемыми. Полная parity этих
вызывающих остаётся за своим тикетом; такая адаптация не является расползанием
объёма.
