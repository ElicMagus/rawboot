# eGON sealer берёт длину контрольной суммы из размера входа, а не из поля заголовка

`seal` (`rawboot-image`) вычисляет дополненную длину образа из фактической длины в байтах
бинарника лоадера и записывает это значение в поле `length` заголовка eGON, прежде чем
просуммировать контрольную сумму с начальным значением. Upstream `mksunxi`, напротив, читает `length` из
переданного ему заголовка, выравнивает его и суммирует столько слов. Оба сходятся только тогда,
когда заголовок уже содержит истинный размер.

Мы расходимся намеренно. Наш runtime размещает фиксированный заголовок-заглушку (`length = 32768`),
а реальный образ лоадера уже превышает его (sealed FEL-лоадер — около 57 КиБ), поэтому доверие
полю заголовка привело бы к суммированию и объявлению меньшего числа байт, чем BROM должен
загрузить, — хвост образа был бы проигнорирован. Вывод длины из буфера не может разойтись с
фактически присутствующими байтами, и BROM всё равно принимает результат, потому что суммирует
ровно тот `length`, который в итоге объявляет заголовок, — значение, записанное самим `seal`.

Это сознательное исключение из правила паритета ADR-0007: наблюдаемое поведение (образ,
валидный для BROM) совпадает с upstream, а вход алгоритма — нет. Альтернатива — зашить реальный
размер в `rawboot-rt` через линкерный символ, как делает upstream `start.S` с `__spl_size`, и
суммировать поле заголовка — была отвергнута как лишняя механика без наблюдаемой разницы. Если
когда-нибудь второй sealer или инструмент прошивки должен будет выдавать побайтово идентичный
результат с `mksunxi`, вернуться к этому.

Последствия: `seal` никогда не читает `length` заголовка; вызывающий код не должен считать
заглушку осмысленной. Раскладка заголовка eGON и его константы остаются единственным общим
определением в `rawboot-image::egon`, встраиваемым `rawboot-rt`.
