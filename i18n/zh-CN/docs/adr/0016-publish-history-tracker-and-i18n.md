# 公开仓库：真实历史、1:1 跟踪器和三语文档

在此决策之前，公开的 GitHub 仓库 `ElicMagus/rawboot` 是一个没有历史的 squash 提交，而决策过程只存在于内部 Gitea 中：标签 `v0.1.0` 之前有 207 个提交、52 个 issue、4 个 PR、72 条评论和 33 条 blocked-by 关系。用户需要决策过程，而项目已完成，之后仅通过修复进行维护。决策：发布经过路径和内容重写的真实历史，在 GitHub 上一对一重建跟踪器，并以三种语言维护文档。

## 历史与发布边界

发布 `master` 截至 `v0.1.0`（含）的历史（207 个提交）以及带注释的标签本身；标签消息、tagger 和日期保留，重写后的目标为新的。迁移和翻译本身的提交作为新的公开提交叠加在上层。

历史由 `git-filter-repo` 重写：作者和提交者日期保留，所有者的真实姓名和邮箱保留。清除令牌和密码、含令牌文件的路径、形如 `/home/<user>` 的家目录路径以及对内部 Gitea 的链接。发布所有与代码、环境和决策相关的内容（包括 `AGENTS.md`、`CODING_STANDARDS.md`、`docs/agents/` 和 `research/`）；保留为内部的是 `.gitea/`、`scripts/export-public.sh`、`scripts/issue-view.sh`、`target/` 和 `embed/`。Force-push 替换先前的 squash 提交。未合并的分支（决策时为 `fix/54`）在合并前保持内部，并通过单独的手动操作发布。

## 跟踪器

Gitea 仍然是规范跟踪器和事实来源；GitHub 获得一对一的归档。编号 1–56 保留：对象严格按升序创建，包括 4 个 PR 在其编号上。PR 以关闭的归档记录形式呈现，带有临时 base 分支和指向真实 merge 提交的链接；带有 Merged 徽章的“重放”被拒绝，因为它会带来新的 SHA 和日期。迁移 72 条评论、标签、里程碑和 33 条 blocked-by 关系——后者通过 GitHub 原生依赖关系。GitHub 上的创建和关闭日期由服务器设置，因此等于迁移日期；原始日期记录在对象正文中。文本双语：英文在上，俄文原文在 `<details>` 中。提交消息保持俄文。

## 文档

英文是事实来源并位于现有路径。俄文和中文翻译以相同的相对路径镜像到 `i18n/ru/` 和 `i18n/zh-CN/` 的树中。翻译整个公开集合，包括 `research/`、`AGENTS.md` 和 `CODING_STANDARDS.md`。API 名称、寄存器名称和词汇表术语不翻译。翻译草稿由代理完成，无需单独审核；所有者在实际使用时修正。版本不一致时以英文为准。

## 验收

推送前必须：Gitea↔GitHub 清单差异（编号、类型、状态、正文、标签、里程碑、评论、依赖）、对所有历史 blob 和所有跟踪器文本进行秘密扫描，以及在公开 HEAD 上运行 `scripts/check.sh`。任何红色检查都会阻止推送。

## 考虑过的选项

- **Squash 提交加上单独的决策历史文档**（已拒绝）：无法提供“决策 → 提交 → PR”的可追溯性。
- **合成的策展历史**（已拒绝）：看起来像真实的，但并非真实。
- **带真实 merge 的 PR 重放**（已拒绝）：以新的 SHA 和当前日期为代价获得 Merged 徽章。
- **引用 merge 提交的归档关闭 PR**（已采用）：历史和日期准确。
- **仅英文或仅俄文的跟踪器**（已拒绝）：要么失去事实来源，要么失去对外国用户的可访问性。
- **在每个文件夹旁放置翻译**（已拒绝）：分散副本并使完整性检查复杂化；采用统一的 `i18n/` 镜像。

## 后果

- 公开的 squash 提交消失；所有指向它的旧链接都会失效。
- `scripts/export-public.sh` 和 `docs/agents/export-public.md` 中“不导出历史”的规则被取消；发布成为单独的流程。
- GitHub 对象的编号在迁移期间冻结：任何多余的 issue 都会不可逆地推动它。
- 内部邮件域在提交元数据中保持可见（所有者的决定）。
- 接受翻译漂移：项目已完成，英文版本仍然是事实。
- `fix/54` 和其他未合并分支仅在合并后发布。
